# B203 输入框玻璃「条纹/格栅」结案报告

日期：2026-10-20 · 结案版本：v5.0.22-test（用户真机确认条纹消失）· 报告整理：v5.0.23

---

## 一、结论（一句话）

**条纹不是"模糊参数"问题，是「走错了分支」——用户设置里 `backgroundEffectType` 的历史残留值 = `GLASS`（液态玻璃），设备一直走 `hazeGlass` 光学折射管线；把输入栏固定回 `BLUR`（原版 3.0.0 的默认分支）后，条纹消失。**

---

## 二、它是怎么"莫名其妙出现"的

### 2.1 时间线

| 版本 | 事件 |
|---|---|
| v4.8.160 | 按用户要求「直接抄原版 2.5.6」，移植了原版的**双分支**：`BLUR`（普通高斯模糊）+ `GLASS`（`hazeGlass` 液态光学玻璃），并加了设置项「背景效果类型」 |
| v4.8.16x | 用户在设置里选过「液态玻璃」→ `displaySetting.backgroundEffectType = GLASS` **写入 DataStore 并永久持久化** |
| v4.8.17x ~ v5.0.21 | 此后每个版本，`chatInputHaze()` 都用 `when (backgroundEffectType)` 分发 → 这台设备**永远走 GLASS 分支** |
| v5.0.16 | 渲染模块「整件照搬上游 3.0.0、逐字 0 diff」——**0 diff 只保证代码一致，不保证运行到同一分支**（用户数据里 GLASS 残留），所以照搬后条纹依旧 |
| v5.0.20 | 又把 GLASS 强制成唯一分支（"统一玻璃"）→ **等于把坑钉死**，条纹必然持续 |
| **v5.0.22** | `ChatInputHaze` 改为**恒定 `hazeBlur`**（BLUR 分支逐字）→ 不再走光学管线 → **条纹消失**（用户真机确认） |

### 2.2 为什么条纹是 GLASS 分支的固有伪影

- `hazeGlass`（液态玻璃）不是普通模糊，而是**光学折射**：它对源做位移采样 + 折射率映射（`optics(blurRadius=16dp, depth=0.5)`）。
- 低分辨率源（输入栏捕获区域有限）+ 光学采样 → **规则采样网格**，表现为 10px 级竖条纹/格栅。
- 与半径、噪点、alpha 全部无关 —— 这就是为什么 v4.8.169/170 把参数域穷尽（半径、噪点、alpha、层数）都没用。
- 像素验尸佐证（v4.8.170 截图）：周期 10px、列亮度自相关 0.84、谐波 21/31/41/52 —— 典型的规则采样网格，不是随机噪声。

### 2.3 为什么"原版正常"

原版 3.0.0 的默认值是 **`BLUR`**；用户在原版上没有 GLASS 的持久化残留 → 一直走 BLUR → 无条纹。
**同一个 APK 代码，两套数据 → 两种分支 → 两种观感。** 这正是"代码 0 diff 仍然修不好"的根源。

## 三、它是怎么"莫名其妙好了"的

v5.0.22 做了两件改动，二者都是"差分归零"：

1. **`ChatInputHaze` → 恒定 `hazeBlur`**（把运行分支钉死在原版默认的 BLUR）
2. **`Theme.kt` 的 `LocalOverscrollFactory provides null` → 注释掉**（对齐上游：上游该行本来就被注释，即启用系统默认 overscroll）

用户真机反馈："**它确实是没有条纹的模糊了**" —— 这一句就是决定性证据：
- 显示的是**模糊**（BLUR）而不是玻璃质感 → 证明代码走的正是 `hazeBlur`
- 条纹消失 → 证明伪影只存在于 `hazeGlass` 分支

**（补充：overscroll 那一行是同一批的第二个变量，属于"顺手归零"；条纹的充分解释已由"分支切换"单独完成。若要严格隔离，可单测"BLUR + 原 overscroll"组合——但从机制上看，overscroll 不参与 haze 的采样管线，不是主因。）**

---

## 四、关于"模糊屏闪"

现象：滚动时，输入栏下方文字进入模糊区，模糊内容随文字位置变化而变化，观感像"闪"。

机制（正常物理）：
- 输入栏的模糊**源**包含消息列表（与原版一致，源注册 3 处）；
- 滚动 → 源内容位置改变 → 模糊层每帧重新采样 → 模糊图案随之流动；
- 这是任何"实时模糊"的固有行为，**原版同样存在**（用户已确认）。

结论：**不是 bug，不需要修**（用户定版：可以不改，原版后续可能自己修）。

| 模糊关闭 | 不透明面板（原版语义） |

## 六、教训（已入册 #141-143）

1. **「代码 0 diff」≠「行为 0 diff」**——运行时分支由持久化数据决定。观感类 bug 排查必须问「真机实际走的是哪个分支」，而不是「代码里有没有这段」。
2. **参数域穷尽后，下一步是「分支/路径域」**——不是继续调半径/噪点/alpha。液态玻璃是独立渲染管线，不是模糊的加强版。
3. **用户设置的历史残留值是隐形输入**——任何"抄原版/对齐上游"的验收，都要连同持久化状态一起归零（或提供一键重置）。

# 工作区定位（2026-11-13 定稿）

工作区不是单一功能，而是**三层身份叠在一起**。后续所有工作区相关改动必须同时满足这三层。

## 1. 工作区 = 执行沙箱

- `files/workspaces/<id>/linux/` 是 Linux rootfs；`workspace_shell` / `workspace_job` 在里运行。
- 能力：apt/pip/npm、编译、文档工具链、浏览器内核、Python/Node。
- 原则：环境可重建，用户文件不可丢；rootfs 是“工具环境”，不是资料本体。

## 2. 工作区 = 文件夹

- `files/workspaces/<id>/files/` 是用户文件树；`/workspace` 在文件工具里按当前 CWD 解析。
- 目录、文件、压缩、导入/导出都是第一等操作；文件路径就是稳定身份。
- `tmp/` 是临时产物，允许清理；`.versions/` 是覆盖写快照，不参与正常浏览。

## 3. 工作区 = 个人资料库

- 用户可以长期存放：项目源码、学习资料、文档、数据集、产出物、个人知识文件。
- 它和聊天记录/记忆库是**不同层**：聊天是过程，记忆是模型的工作知识，工作区是用户的资料本体。
- 备份必须能带走整个工作区（files + linux），恢复后路径不变、环境可继续用。
- 删除/清理必须区分“临时产物”和“用户资料”；默认不删用户文件。

## 边界（不可混淆）

| 层 | 位置 | 是否用户资料 | 是否可重建 |
|---|---|---|---|
| 聊天/记忆数据库 | `databases/` | 是 | 否（需备份） |
| 工作区文件 | `workspaces/<id>/files/` | **是** | 否 |
| 工作区环境 | `workspaces/<id>/linux/` | 半是（用户装的依赖） | 可重建但优先保留 |
| 临时产物 | `workspaces/<id>/tmp/`、`.tmp/` | 否 | 是 |
| 上传收件箱 | `files/upload/` | 是（附件实体） | 否 |

## UI 语义

- 工作区列表 = 资料库入口；工作区详情 = 文件/环境两个视角。
- “应用文件”是工作区文件，不是 App 私有缓存。
- 未来新增“资料/知识”视图时，仍以 `files/` 为唯一实体，不另建平行存储。

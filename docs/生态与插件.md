# 生态与插件 — 架构与运行机制（v4.6.4）

> 本文档为 RinCore "生态与插件"模块的单一事实源：架构、数据流、运行兼容矩阵、行为定版。
> 维护约定：任何涉及包解析 / 工具注册 / 执行桥 / 播种逻辑的改动，必须同步更新本文档并随代码提交。

## 一、模块定位

RinCore 吸收 Operit 生态的落点：**包（工具包/插件）在此管理，启用后转化为模型工具，与主聊天双并行**。

```
设置 → 数据与日志 → 更多设置
  ├── 生态与插件（统一页 — OperitEcoPage）    ← 本模块（三 Tab）
  │     ├── Tab① 工具包：内置 31 包 + 市场包（script/package）
  │     ├── Tab② 插件：workspace 插件（.plugins/ 目录即安装）
  │     └── Tab③ 面板：带 UI 的插件面板（独立 WebView 渲染管线）
  └── 应用市场（MarketPage）                   ← 在线浏览/下载/安装
```

## 二、包从哪来（三个来源）

| 来源 | 形态 | 存储 | 管理方 |
|---|---|---|---|
| **内置包（31 个）** | `assets/operit-packages/*.js`（METADATA 头 + exports 工具函数） | 播种释放到 `files/operit_packages/script/builtin_*.js` | 播种器 `OperitBuiltinPackages` |
| **市场包** | 市场 API 下载（script / toolpkg 目录） | `files/operit_packages/<type>/<安装目录>` | `MarketInstallService` |
| **workspace 插件** | 文件区 `.plugins/<名>/`（plugin.yaml + SKILL.md + 桥脚本） | workspace 沙箱文件区 | `PluginManager` |

**唯一数据信源**：内置包与市场包统一入 `InstalledPackageStore`（DataStore + 文件目录），生态页 / 工具注册 / 开关全部读它。

## 三、包怎么跑（运行机制全链）

```
① 加载     InstalledPackageStore.listInstalled()
② 解析     ScriptMetadataParser.parse(js文本)   ← METADATA 块 → ScriptMetadata
             ├─ ① isLenient JSON（规范格式）
             ├─ ② HJSON（org.hjson — 与 Operit 同款；无引号/注释/省略逗号/三引号全兼容）
             ├─ ③ JS 对象修复链（兜底）
             └─ ④ parseLoose 简化提取（极端宽松时保名称/描述）
③ 注册     OperitToolProvider.createScriptTools()
             → 工具名 operit__<包>__<函数>（全局唯一, 上限截断）
             → 工具域「插件」，启用即注入模型
④ 执行     model 调用工具 → OperitScriptRuntime.executeTool()
             → QuickJS 执行脚本源码
             → exports[函数名](params)   ← 与 Operit 脚本导出约定一致
             → 宿主桥 __hostCall 提供运行能力（见下）
⑤ 返回     结果 JSON → 工具输出
```

**实测基准（31 内置包）**：HJSON 路径 **31/31 全通过，247 个工具声明全量解析，零重名**。

## 四、运行兼容矩阵（宿主桥能力）

JS 脚本通过 `__hostCall(name, argsJson)` 访问宿主。当前接通面：

| 能力 | 桥方法 | 状态 |
|---|---|---|
| 文件读写 | `files.read/write/mkdir/exists/delete/list/move/copy` | ✅ 接通（隔离目录 `files/operit_runtime`） |
| HTTP | `http.request`（GET/POST/PUT/PATCH/DELETE，超时/请求头全支持） | ✅ 接通（RinCore OkHttp） |
| JS 版 OkHttp DSL | `OkHttp.newBuilder()...execute()`（github 等 TS 编译包专用模式） | ✅ 接通（桥到 http.request） |
| 工具侧 HTTP | `Tools.Net.httpGet/httpPost/fetch` | ✅ 接通 |
| shell / 终端 | `system.shell` / `Tools.System.terminal.hiddenExec` | ✅ 接通（⚠️ 需存在 shell READY 的 workspace；无则明确报错） |
| 设备信息 | `Tools.System.getDeviceInfo` | ✅ 基础值 |
| 消息/记忆/UI/蓝牙/工作流/平台设置 | `Tools.Chat/Memory/UI/bluetooth/Workflow/SoftwareSettings` | ❌ 明确降级：返回 `capability not implemented`（不静默假死） |

**兼容原则**：能通的真接通；不能通的**必须返回结构化错误**（`{success:false, message:...}`）——禁止"显示可用但运行无响应"。

## 五、行为定版（不可回退的语义）

1. **播种记忆**：内置包播种记录在 `InstalledPackageStore.seededEntries`（DataStore）。**用户卸载过的内置包不再复活**（含升级路径）；旧版已播种用户迁移时自动打标全量资产。
2. **内置包不提供卸载**（自带能力，开关=停用等效）；市场包可卸载。
3. **开关语义**：`setEnabled` → `OperitToolProvider.refresh()` → 工具注册/注销即时生效。
4. **插件页与生态页分工**：设置→插件页只显示**真从市场安装的**；内置包只在**生态与插件**页（防"没装却有插件"的混淆）。
5. **解析链顺序固定**：isLenient → HJSON → 修复链 → 简化提取（HJSON 为手写格式正解，压阵）。
6. **工具名规则**：`operit__<sanitized包名>__<sanitized函数名>`，全局去重，长度受控。

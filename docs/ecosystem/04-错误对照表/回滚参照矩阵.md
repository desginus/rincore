# 回滚参照矩阵

更新日期：2026-08-06
用途：问题解决不了需要回滚时，立刻查此矩阵——该域回滚到哪个版本最合适、哪些文件动、哪些文件不能动。
原则：按问题域回滚，不整体回滚；保护其他域的修复成果。

## 回滚决策流程

1. 判断问题属于哪个域（传输层/缓存/工具域/MCP/收尾/UI）
2. 查本矩阵的"回滚参照版本"和"回滚文件集"
3. 只 checkout 该域文件，其他文件保持不动
4. 回滚后验证：目标问题是否消失 + 其他域是否正常（重点回归连接/缓存/工具）
5. 记录回滚原因和结果到 03 修改全记录

## 各域回滚参照

### 1. 传输层（连接/流式/消息拼装）——最高危域

- 回滚参照：v3.2.2（v3.5.0 已验证过整体回滚可行）
- 回滚文件集：OpenAIProvider.kt / ChatCompletionsAPI.kt / ResponseAPI.kt / Message.kt / GenerationHandler.kt / PlaceholderTransformer.kt / PromptInjectionTransformer.kt / ChatService.kt
- 保留项（回滚时不能动）：流式落盘（v3.4.6）、FGS 类型（v3.4.4）、AlarmScheduler DI（v3.4.2）、保活/权限/闹钟/工作流、MCP 管理/域分类/工具路由
- 注意：v3.5.0 回滚后暴露 70K 注入（v3.5.1 修）；回滚后若工具池大需补瘦身
- 细分回滚：
  - 只回连接配置 → v2.9.8 的 DataSourceModule（HTTP/1.1 + 连接池 + 超时）
  - 只回流式解析 → 原版 fork-ref 的 ChatCompletionsAPI（无重试无 watchdog）
  - 只回中断处理 → 移除静默恢复 + 保留 v2.9.8 重试（当前状态，勿回退）

### 2. 缓存（system 构建/请求体）——次高危域

- 回滚参照：v3.5.11（SystemPromptBuilder stable/volatile，用户确认缓存正常）

### 6. 保活/权限/闹钟/工作流（独立模块）

### 7. UI 层（设置/域管理/聊天页）

- 回滚文件集：按具体页面
- 保护项：ErrorCard 弹窗细化（v3.5.16）、ChatMessageReasoning 计时兜底

## 回滚禁忌（历史教训）

1. 禁止整体回滚到旧版本（会丢失其他域修复）——按域回滚
2. 禁止回滚 limitContext 相关（D5：勿启用）
3. 禁止回滚到 HTTP/2 优先（PROTOCOL_ERROR）
4. 禁止回滚静默恢复逻辑（中断被吞）
5. 禁止回滚 keepalive 到 5min+（陈旧连接 EOF）
6. 回滚后必须验证缓存（请求体稳定）和连接（中断可见）

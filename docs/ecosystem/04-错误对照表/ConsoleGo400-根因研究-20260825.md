# Console Go 400 (2013) 根因研究全记录 (2026-08-25 闭合)

## 现象链 (用户实测, OpenCode 网关)
- 新窗口 Minimax: 正常
- 旧窗口历史含千问回复 → Minimax: 400 (2013)
- 旧窗口历史含 DeepSeek 回复 → Minimax: 正常
- 千问走 Anthropic 接口 (ClaudeProvider), DeepSeek 走 OpenAI 接口 (ChatCompletionsAPI)

## 根因 (铁证链)
1. 千问 (Anthropic 通道) 回复带 thinking 块, OpenCode 网关不自签
   → ClaudeProvider SSE parse (thinking_delta/signature_delta) 保存为
   无签名 UIMessagePart.Reasoning part
2. v3.10.4 原码 (3.11.0) ClaudeProvider.toContentBlock Reasoning 分支:
   ```kotlin
   is UIMessagePart.Reasoning -> buildJsonObject {
       put("type", "thinking"); put("thinking", reasoning)
       metadataAs<ClaudeReasoningMetadata>()?.signature?.let { put("signature", it) }
   }
   ```
   → 无条件回发 thinking 块 (无论有没有签名)
3. Minimax Anthropic 兼容上游严格校验: 历史 thinking 块必须带 signature
   → 无签名 thinking → invalid params 400 (2013)
4. DeepSeek (OpenAI 通道) 在 OpenCode 场景 reasoning_content 为空
   → ChatCompletionsAPI parseMessage (reasoning.isNullOrEmpty() 检查)
   → 历史无 Reasoning part → Minimax 正常
5. 新窗口无历史 → 正常

## 修复 (v3.10.12 起在 main 常驻)
```kotlin
is UIMessagePart.Reasoning -> {
    val sig = metadataAs<ClaudeReasoningMetadata>()?.signature
    if (sig != null) { /* 官方 Claude 历史: 带签名发 thinking */ }
    else null   // 无签名: 丢弃 — 兼容网关历史不回发 thinking
}
```
- 官方 Claude 历史 (有签名): 保留完整 thinking 协议
- 千问/兼容网关历史 (无签名): 丢弃, Minimax 不再 400
- v3.10.14 追加: 非官方 host 不发请求级 thinking/cache_control/output_config
- v3.10.15 追加: BOM strip + max_tokens 非官方兜底 8192 + REQ_META

## 教训
- 400 排查期间多轮猜测 (thinking 参数/max_tokens/空块/连续 user/私有字段)
  均未命中 — 命中需要"场景差异对照"(千问 vs DeepSeek vs 新窗口) 而非
  请求体猜测。以后同型问题先做场景差量实验。
- 原版无此问题: 原版历史中无千问 thinking 块场景 (原版用户网络缓存或
  网关行为不同), 故原版一切正常 — "原版好了" 与 修复 并存不矛盾。

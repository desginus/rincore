## 连接类错误详表（3.x 中断问题全链）

### B21. stream was reset: PROTOCOL_ERROR（v3.5.17 根治）
- 现象：流式生成中报 okhttp3.internal.http2.StreamResetException: stream was reset: PROTOCOL_ERROR
- 根因：HTTP/2 连接问题。DeepSeek 服务端 ALPN 协商到 h2 后连接异常
- 关键认知：protocols(HTTP_1_1, HTTP_2) 的顺序不影响 ALPN 结果，服务端支持 h2 必选 h2。唯一可靠方案是协议列表只留 HTTP_1_1
- 修复：DataSourceModule protocols(listOf(Protocol.HTTP_1_1))
- 引入点：v3.1.0 显式 HTTP_2 优先

### B22. unexpected end of stream（v3.5.17 根治）
- 现象：java.io.IOException: unexpected end of stream，EOFException \n not found: limit=0（Http1ExchangeCodec.readResponseHeaders）
- 根因：连接池复用陈旧连接。服务端空闲关闭连接后，客户端连接池仍保留（keepalive 5min），复用即 EOF。工具执行 60s+ 后请求必触发（空闲超服务端关闭时间）
- 修复：ConnectionPool(12, 60s) keepalive 低于服务端空闲关闭时间；writeTimeout 120s；重试 3→5 次
- 引入点：v3.1.0 连接配置改动（ConnectionPool 10min→5min keepalive）

### B18. 流式中断静默恢复（v3.5.17 根治）
- 现象：工具轮后请求返回空/回复缺失，无任何报错，日志 SEND→RECV 正常、FINISH 正常、messages 无新增
- 根因链：v3.1.0 三 Provider 同时引入静默恢复（onFailure 时 hasData=true 直接 close()）；v2.9.8 的正确机制（未收到数据重试）在 v3.5.0 回滚时丢失；3.5.14 重复引入
- 修复：移植 v2.9.8 重试机制；三 Provider 静默恢复全部移除
- 铁律：禁止任何静默吞错逻辑；中断必须可见或自动重试；连接层正确参照是 v2.9.8

### B7. Required SETTINGS preface not received
- 现象：DeepSeek 服务端报错弹窗（只有一句话，无状态码），工具调用时/后高发
- 根因（最终）：所有子请求（标题/建议/背景文本/工具分类）首条消息是 user 无 system，DeepSeek V4 Flash 要求首条 system
- 修复：OpenAIProvider.generateText 统一兜底前置空 system（幂等）；HTTP/1.1 优先
- 误区记录：曾误判为 400/effort 档位问题（用户开 AUTO 不触发）；曾误判为 HTTP/2 SETTINGS 帧问题

### 中断排查方法论（用户强制要求）
- 不接受偶发/概率性作为最终结论
- 日志必须完整：Trace ID 随机 UUID、事件计数正确、错误上下文（model/baseUrl/msgs/tools/reasoning）
- 对比法：git log 找问题首次引入版本 → 对比该版本与上一版本
- 连接层对比参照 v2.9.8，不是原版 fork-ref

## 监控项（测试重点）

1. 后台运行 + 长文本 + 工具调用场景：中断是否消失
2. 缓存命中率：请求体稳定后是否恢复
3. 工具执行超时后的继续生成：陈旧连接是否规避
4. 停止生成/中断后：计时器、灵动岛是否正常收尾
5. MCP 连接失败：状态显示和错误信息是否明确

## 核心铁律（违反即翻车，改动前必读）

1. 请求体零改动原则：system 提示、tools 数组、域概览任何变化都会破坏缓存前缀，改动前必须评估缓存影响
2. 连接层参照 v2.9.8：自己 2.x 稳定版是连接行为的正确参照，不是原版 fork-ref
3. 禁止静默吞错：中断必须可见（报错）或自动重试，任何 close() 吞异常的行为都是 bug
4. 协议合规优先：首条消息必须 system，缓存优化只能在协议约束内做
5. 版本号锁定前两位，只能递增第三位
6. 推送不等于交付 APK，用户只能测试 APK
7. limitContext 勿重新启用（D5），启用即破坏缓存
8. 补丁式修复不可接受，必须找到根因做架构级深修

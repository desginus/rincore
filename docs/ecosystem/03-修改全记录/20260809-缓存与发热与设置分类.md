# 2026-08-09 v3.5.59 — 缓存确定性 / 发热根治 / 落盘权衡 / 设置分类

## 一、发热根因定位 (用户实测: 模型工作时明显发热)
审计结论:
- CallTracer 内存态 (events + StateFlow), 不写盘 — 非发热源
- 工具描述无运行时状态 (时间戳均在 execute 内) — 非缓存破坏源
- 主因: 流式期间每 chunk 全量 saveConversation (全量序列化 + 写库,
  每秒数十次全量 IO) — 生成期发热的直接来源

## 二、落盘权衡 (用户要求: 不能全删, 切出切回内容不能丢)
- 原: 每 chunk 落盘 → 内容保真但发热
- 现: UI 内存更新保持每 chunk (显示流畅), 落盘降为每 2s 一次
  → IO 降 95%+, 丢失窗口 ≤2s (切出/进程被杀最多丢 2s 已生成内容)
- 收尾 (onCompletion) 仍全量落盘 — 生成完成不丢

## 三、断流重试 2 → 5 次 (用户要求)
- 重试间隔退避 1s/2s/4s/8s (前几次缓存命中快速恢复, 后续防风暴发热)
- 重试消息相同 → 缓存命中, 不额外破坏前缀

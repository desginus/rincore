# v3.10.1 / v3.10.2 高危修复 (2026-08-24)

## v3.10.1 — 缓存命中率暴跌根因: 占位符时间注入破坏请求体前缀
现象: DeepSeek 冷启动 12K+ 仅命中 5.4K (等于 system 全命中, 断点后全 miss)。
根因: PlaceholderTransformer 时间占位符 (cur_date/cur_time/cur_datetime) 原用
LocalDate.now()/LocalTime.now()/LocalDateTime.now() 实时求值; 转换器作用于全部
消息文本 (含 system 与历史), 文本中含有占位符时每轮渲染字节不同 → 请求体
前缀逐轮漂移 → 缓存断开。
修复: 时间占位符基准改为会话时间 (首条用户消息 createdAt), 同会话跨轮字节
一致, 缓存前缀稳定; 语义正确 (占位符应表示发消息时刻)。

## v3.10.2 — GPT-5.6-Luna (Opencode 订阅) 思考链完全丢失
现象: 经 Opencode 网关的 GPT 5.6 Luna 只显示正文, 思考链完全不生成。
根因: parseMessage 对 content 数组 thinking 块提取只兼容 Mistral 单层形态
(content[0].thinking[0].text); 网关发 thinking 直接带 text / thinking 字符串 /
多块时全部丢失。
修复: thinking 块提取泛化 — text 直达 / thinking 嵌套逐项 / 字符串直达 /
多块拼接 / 空块过滤; 顺序 reasoning_content > reasoning > content 数组。

## v3.5.x 详细记录

### v3.5.17（当前，2026-08-05 起，连接根治系列）

阶段一：缓存回滚（1784ba75）
- 回滚 3.5.16 请求侧改动：use_skill 移出框架工具集（tools 数组恢复）、UNCLASSIFIED 域移除（layer1 恢复）
- 原因：3.5.16 改动请求体导致缓存率暴跌（用户实测）
- 保留：P0 修复（子请求 system 兜底不影响主请求）、弹窗细化、Trace ID、计数、list_domains

阶段二：连接层回滚（6161dd99 → 0a229541）
- readTimeout 恢复又按用户指示定回 3min
- SSE 无数据看门狗取消主动断开，只记录日志
- 原因：3.5.14 引入的主动断开机制是中断元凶

阶段三：静默恢复移除 + content 数组解析（1f9d350e → 60389917）
- ChatCompletionsAPI/ResponseAPI/ClaudeProvider/GoogleProvider 全部移除 hasData 静默 close
- 根因：v3.1.0 引入的三 Provider 静默恢复，中断被吞无报错
- parseMessage content 数组拼接对齐原版（数组格式 content 不再丢失）

阶段四：v2.9.8 SSE 重试机制移植（98f5d7d6）
- hasReceivedData/retryCount/maxRetries/currentEventSource/connect() 完整移植
- 未收到数据自动重试，收到数据后中断传播异常
- 这是 2.x 稳定期的关键机制，3.5.0 回滚时丢失

阶段五：MCP 状态撕裂修复（7ecda960）
- addClient 的 getTransport 包 runCatching（stdio 失败不再中途退出）
- getAllAvailableTools 过滤 Error 状态服务器
- callTool 报错明确化
- 经验文档固化：B18/B19/缓存教训写入 rincore-bug-record

阶段六：完全禁用 HTTP/2（b27253cd → 895725c4）
- protocols 只留 HTTP_1_1
- 根因：DeepSeek 服务端 ALPN 协商到 h2 后报 stream was reset: PROTOCOL_ERROR
- protocols(HTTP_1_1, HTTP_2) 顺序不影响 ALPN，服务端支持 h2 必选 h2

阶段七：计时器/灵动岛收尾（f9ea683a → 520b4cb0）
- onCompletion 收尾包 NonCancellable（取消态也执行落盘 + 生成结束事件）
- stopGeneration 显式 tryEmit ChatGenerationEnded
- 根因：job.cancel() 后 onCompletion 挂起调用跳过，灵动岛不取消、计时器不停

阶段八：连接配置对齐 v2.9.8 + keepalive 60s（75c8e595）
- writeTimeout 120s、ConnectionPool(12, 60s)、pingInterval 30s
- 根因：工具执行 60s+ 后连接空闲超服务端关闭时间，复用陈旧连接 EOF
- SSE 重试 3→5 次（指数退避 31s 窗口）

# v3.10.3 — Opencode 各套餐 HTTP 500 根因修复 (2026-08-24)

## 现象
经 OpenCode 订阅套餐的模型大概率无法使用, 服务端返回 HTTP 500。
存在很久 (v3.5.16 引入), 原版 RikkaHub 完全正常。

## 根因链条
1. v3.5.16 P0-1: DeepSeek 要求首条消息为 system; 子请求 (标题生成/
   建议生成/上下文压缩/背景文本) 首条是 user, 当时插入空字符串 system
   兜底 — DeepSeek 只认角色存在不查内容, 对 DeepSeek 有效
2. Opencode 网关对 {"role":"system","content":""} 返回 HTTP 500 —
   所有经 OpenCode 的模型在标题/建议/压缩等后台子任务稳定失败;
   主聊天链路 fullSystem 恒非空不受影响
3. 原版无此兜底 (直接发纯 user 序列) 故一直正常

## 修复
- MessageProtocol.ensureSystemFirst 三处空 system 改最小非空前言
  FALLBACK_SYSTEM_PROMPT = "You are a helpful assistant."
- OpenAIProvider.generateText 子请求兜底同步替换
- 全仓 UIMessage.system("") 注入点清零

## 教训
协议兜底不能发送"结构性合规但语义为空"的内容 — 不同网关对
空字段容忍度不同, DeepSeek 接受不代表其他网关接受。
兜底内容必须本身是合法有效的请求成分。

## 验证路径
OpenCode 套餐模型对话后观察标题是否生成/建议是否出现,
运行日志确认无 HTTP 500; DeepSeek 正常对话回归。

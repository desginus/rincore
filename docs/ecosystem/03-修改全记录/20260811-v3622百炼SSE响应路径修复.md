# 2026-08-11 v3.6.22 — 百炼 SSE 响应路径修复 (Streamable 兜底)

## 用户实测反馈 (v3.6.21)
- 重连重试后仍报 job was cancelled → 非偶发断流 → 百炼端点确定性行为差异
- 其他 SSE 服务器正常 → SDK 的 SseClientTransport 对标准 SSE 无问题
- 百炼特有 → 响应路径差异

## 根因分析 (高置信度)
- SseClientTransport.performSend: POST endpoint 后丢弃响应体, 只从 SSE 流收响应
  (标准 MCP SSE: POST 返回 202, 响应经 SSE 流)
- 若百炼把工具响应放 POST 响应体 (非标准 SSE 或兼容 Streamable):
  SDK 永远等不到 SSE 流响应 → 百炼关闭流/网关断开 → handlerScope 取消
  → "Job was cancelled"
- 其他 SSE 正常 = 它们遵循标准 (响应经 SSE 流)

## 修复 (v3.6.22)
- callTool 取消时 (生成活跃):
  1. 重连重试一次 (SSE 断流场景 — v3.6.21 保留)
  2. 仍失败且是 SseTransportServer → 转换 StreamableHTTPServer (同 id/URL)
     → addClient 重连 → 再试一次
     - StreamableHttpClientTransport 读 POST 响应体 (JSON → _onMessage)
     - 兼容两种响应路径: 202+SSE 流 / 200+JSON
- 其他 MCP/用户停止路径不受影响 (仅取消且活跃时触发, 仅 SSE 类型兜底)

## 预期
- 百炼端点若支持 Streamable POST → 工具响应直接拿到 → 修复
- 日志 "falling back to StreamableHttp" 出现 = 兜底生效

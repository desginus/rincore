
## ai 模块（传输层，修改高危区）

| 文件 | 职责 | AI 修改入口标注 |
|------|------|----------------|
| provider/providers/openai/ChatCompletionsAPI.kt | DeepSeek/OpenAI 流式主通道 | SSE 重试机制在此（v2.9.8 移植，勿删）；watchdog 只日志不动作；content 数组解析必须保留数组拼接 |
| provider/providers/openai/ResponseAPI.kt | Responses API 流式 | 与 ChatCompletionsAPI 同步维护，禁止两文件行为漂移 |
| provider/providers/OpenAIProvider.kt | 生成入口 | generateText 子请求 system 兜底在此（首条非 system 前置空 system） |
| provider/providers/ClaudeProvider.kt / GoogleProvider.kt | 其他 Provider | 与 OpenAI 对齐，禁止单独引入静默恢复 |
| core/Tool.kt | 工具抽象 | systemPrompt 默认空；工具加入请求 tools 数组会改变请求体 |
| ui/Message.kt | 消息模型 | limitContext 函数在此但禁用；finishReasoning 收尾在此 |
| util/TraceLogger.kt | 诊断日志 | Trace ID 随机 UUID；trace_end 计数注意求值顺序 |

传输层铁律：
1. 中断必须可见或自动重试，禁止静默 close
2. 请求体（system/tools/messages 结构）零改动原则
3. 改 ChatCompletionsAPI 必须同步检查 ResponseAPI
4. 连接配置（DataSourceModule）参照 v2.9.8，HTTP/2 已禁用勿重新启用

## app/data 数据层

| 子包 | 职责 | 关键文件 |
|------|------|----------|
| data/ai | 生成编排 | GenerationHandler.kt（system 构建/工具注入/分层调用）、MessageProtocol.kt（首条 system 保证）、DynamicTools.kt（每 step 重取工具） |
| data/ai/tools | 工具体系 | SkillsTools.kt、workspace 工具、invoke_tools 入口 |
| data/ai/tools/routing | 域分类引擎 | ToolDomain.kt（域枚举）、ToolRouter.kt（工具归域） |
| data/ai/mcp | MCP 管理 | McpManager.kt（addClient/getTransport/callTool，注意 getTransport 必须在错误处理内） |
| data/model | 模型 | Assistant.kt、Settings.kt（SSOT：settingsFlow） |
| data/repo | 存储 | ConversationRepository.kt 等（勿改落盘机制） |

关键链路：
- SSOT：settingsStore.settingsFlow.value，UI/list_domains/invoke_tools/Prompt 四投影由此派生
- 分层调用：模型 → invoke_tools("域") → DynamicTools.getAllAvailableTools → ToolRouter 归域 → execute
- MCP 四方统一：服务器列表 → 工具管理 → invoke_tools → 域地图（mcp__服务器__工具）

## app/service 服务层

| 文件 | 职责 | 标注 |
|------|------|------|
| ChatService.kt | 生成编排核心 | onCompletion 收尾必须 NonCancellable（取消态也落盘+通知）；stopGeneration 显式发生成结束事件 |
| ChatNotificationManager.kt | 灵动岛/通知 | ChatGenerationEnded 必须到达才取消灵动岛 |
| 保活相关 | 后台保障 | 用户环境已满足权限，勿以用户侧原因搁置问题 |

## app/di 依赖注入

- DataSourceModule.kt：OkHttpClient 配置。HTTP/2 完全禁用（protocols 只留 HTTP_1_1）；ConnectionPool(12, 60s)；readTimeout 3min（用户确认）；writeTimeout 120s
- 连接配置修改参照 v2.9.8，keepalive 60s 是防陈旧连接的关键

## ui 界面层

- ChatMessageReasoning.kt：思考链计时（finishedAt 兜底 ZERO，实时累计依赖收尾设置 finishedAt）
- ErrorCard：错误弹窗细化（类型/时间戳/Trace ID/堆栈/复制）
- 设置页/域管理页：工具域分类 UI

## 高风险修改点汇总（改前必查）

| 位置 | 风险 | 约束 |
|------|------|------|
| GenerationHandler system 构建 | 缓存破坏 | stable/volatile 分区，请求体零改动 |
| ChatCompletionsAPI onFailure | 中断被吞 | 禁止静默 close，重试机制保留 |
| McpManager addClient | 状态撕裂 | getTransport 必须在 runCatching 内 |
| ChatService onCompletion | 收尾丢失 | 必须 NonCancellable |
| DataSourceModule protocols | PROTOCOL_ERROR | HTTP/2 禁止启用 |
| Message.kt limitContext | 缓存报废 | 勿重新启用（D5） |
| 任何 tools 数组改动 | 缓存失效 | 先评估缓存影响 |

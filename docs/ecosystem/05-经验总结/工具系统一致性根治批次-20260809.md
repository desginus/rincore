# 批次经验总结 — v3.5.49 ~ v3.5.57 工具系统一致性根治

## 背景
用户实测 4 信息源交叉验证 (list_domains/invoke_tools 帮助/search_domains/实际加载),
连续三轮报告一致性 bug。本批次按根因重写而非补丁, 每轮本地逻辑测试 + CI 验证。

## 已根治问题
1. 计数口径: UI 曾 sumOf 子域+直接 (显示 18 下钻 8) → 统一直接工具数 = 下钻可见数
2. 幻影域: metaToolNames 曾返小写 system (与枚举「系统」并列) → 归枚举
3. Skill 自相矛盾: invoke_tools 独立 skills 参数 (过滤列表 vs 挂载列表) → 移除,
   技能信息只来自工具池 (skill__ 全量) + overrides 挂载
4. 框架工具失踪: v3.5.52 误过滤框架 → 系统域展开空 + workspace 失踪 →
   v3.5.56 回归全量池; workspace_ 加系统前缀
5. 分类误判: 关键词匹配含描述 (search/query/find 误归搜索) → 仅名称匹配 +
   过泛词清理 (query/查/查询)
6. MCP 拆散: 按单工具关键词分类 → 按服务器整体归类 (映射→域, 无映射→未分类)
7. 同名工具重复注册: classifyAll 按名去重
8. 展示路径不可用: 路径（显示名）复制调用报未知 → resolveDomain 剥离括号/
   前缀; 末段模糊匹配兜底
9. 关键词截断: 8+等N个 vs 反查完整 → 全入口完整展示不截断
10. 域名称多入口不一致: 下钻标题用裸路径 → formatDomainLabel 单套生成全入口
11. 声明与运行脱节: "所有工具可直接调用" 不实 → 引导语如实 (加载后调用跨轮保持)
12. 计数与下钻错域: 带括号路径解析失败落到错域 → resolveDomain 兼容后消除

## 核心方法论
- 单一数据链: buildAssistantToolPool → classifyByName → unifiedDomainView →
  所有视图只读 (帮助/List Domains/Search/UI/对照/内置工具/系统提示)
- 名称: formatDomainLabel 单套生成 (路径（显示名）), 全入口一致, 可回解析
- 关键词: 单源 (getKeywords 配置), 全入口完整展示, 静态动态逐字一致
- 分类: 名称优先 (第1元工具/第2系统前缀/第3技能/第4MCP服务器/第5关键词/兜底)
- 修改纪律: 本地逻辑测试 (Python 模拟核心逻辑) + CI 绿才交付;
  禁止边改边推, 改完验证再推

## 缓存相关结论
- layer1 纯配置派生 (枚举域树 + 显示名/描述/关键词), 无运行时数据 — 公共前缀恒定
- tools 数组唯一动态 = 分层加载 (机制内, 加载完稳定)
- memory volatile 低频
- 待办: 缓存阶梯化 (仅 6K 命中) 仍未根治 — 下一批深度排查

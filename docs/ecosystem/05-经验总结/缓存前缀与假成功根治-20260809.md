# 批次经验总结 — v3.6.9 ~ v3.6.10 缓存前缀 / 删除假成功 / 计数统一

## 1. 缓存上百K只命中十几K — 根因: loadedDomains 排序破坏前缀
- 现象: 请求上百K tokens 只缓存十几K (≈system 前段)
- 根因: tools 数组构建最后 .sortedBy{name} 整体重排 — 对话中加载新域后,
  新域工具按名字插入中间位置 → 后续所有工具移位 → 请求前缀在插入点断裂
  → 只有 system 前段命中
- 修复 (v3.6.10):
  - loadedDomains: Set → List (Conversation/GenerationChunk) — 加载顺序持久化
  - 工具构建: LinkedHashSet 保序, 新域追加尾部 (前缀前段不变), 域内名字序
    (确定性), 去掉整体重排
- 效果: 同对话内加载新域, 旧前缀段继续命中 (前缀只增长不重排)

## 2. 内置空域删除无效/静默假成功
- 现象: 物理引擎等内置空域删除后仍存活; 返回成功但实际没删
- 根因: manage_domain 工具直接使用模型传入的 name — 模型从帮助复制
  「路径（显示名）」格式 → 与枚举 label 不匹配 → removedBuiltinDomains
  写入错误名 → 枚举域未删 (静默假成功)
- 修复: manage_domain 域名规范化 (剥离括号/短名解析/显示名覆盖 → 完整路径)
- 注意: 所有域操作工具必须规范化域名 (UI 已传纯路径, 工具侧需兜底)

## 3. Help 计数与 Invoke Tools 输出脱节
- 现象: 系统域 Help 4 vs 输出 11; 文件域 19 vs 24 — 子域计数之和恰好对齐
  掩盖域级差异, 只有单域加载才暴露
- 根因: counts/subtreeCounts 排除框架 (v3.6.1) 但 invoke_tools 加载域输出
  含框架工具 (classified 全量) — 计数口径与列表口径不一致
- 修复: invoke_tools 加载域输出过滤框架 (与计数同口径) + 框架工具附注列出
  (系统域可见性保留)

## 核心方法论
- 缓存: 请求前缀必须"只增长不重排" — 任何全量排序都在加载新内容时断裂前缀;
  确定性排序只能用于"不增长"的部分 (域内)
- 域名: 模型可操作的任何入口必须统一规范化 (剥离显示名 + 短名解析),
  禁止直接用原始输入匹配配置
- 计数: 计数口径必须与工具列表口径完全一致 (排除框架就全程排除,
  含框架就全程含) — 附注可见性

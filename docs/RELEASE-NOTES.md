## RinCore v5.3.42
★★沙箱一体化：默认复用常驻会话（每条命令不再付 1~3 秒启动）+ 预热不再产生 43MB core dump + Linux 能力实测🔧**这一版没有新功能 —— 它把「沙箱」从外挂变成了地基。** **━━ 一、先摆事实：沙箱其实早就是同一套 ━━** 我在沙箱里实测了 9 项：rootfs 是 **Ubuntu 24.04.3**（真用户态）；`/workspace` 挂的就是你在 App 里看到的那个工作区 `files/` 目录（`ProotShellRunner:103`）；`/skills`、`/builtin_skills`、`/tool_outputs`、`/upload` 四个挂载模型和我共用；`/dev/shm` 已自建（Python multiprocessing 能用）。**→「分离」不在目录和挂载这一层，那一层本来就是一套。** **━━ 二、真正的分离在「会话层」：每条命令都重启一次沙箱 ━━** 此前每次 `workspace_shell` 都新起一个 proot 进程，要重新载入 rootfs、重建全部挂载，**单条命令有 1~3 秒是纯启动开销**，`cd` 和环境变量也不跨调用保留。这正是「沙箱慢得惊人」「渲染/转换特别慢」的第一大来源，也是模型宁愿用 shell 做文件操作（等于再付一次启动）的诱因。 **本版改为默认复用**：连续命令共享同一个常驻 proot+bash，**第 2 条起只剩命令本身耗时**。 敢改默认值，是因为复用的安全性早就逐条补齐了：会话 key 含工作区 ID（**不同工作区绝不串进程**）；每条命令前重设 cd（v5.3.37，**cd 不跨命令污染**）；进程死/读线程断会自动重建（**模型跑 exit 也不会永久坏**）；闲置 5 分钟自动关；**起不来自动回退一次性**。 需要干净隔离环境时，传 `session="none"` 即恢复旧行为。 **━━ 三、预热不再往你的工作区里扔 43MB 垃圾 ━━** 上次清理环境时发现根目录有个「文件名是一个空格」的 43.4MB 文件 —— 它是 `officecli --version` 崩溃产生的 **core dump**。而预热的第一步动作**正好**是它，且落在当前工作目录（= 你的工作区）。**意味着每崩一次就吃 43MB，文件名你根本不会注意到。** 本版三处修：命令前置 `ulimit -c 0`（**崩了也不再产生文件**）；探测从 `--version` 改 `--help`（同样把 34MB 二进制走热，避开崩溃路径）；**连续 3 次失败即禁用预热 24 小时**（旧实现每个输入沿都重试 = 反复制造垃圾）。 顺带修掉一个我自己写错的地方：`executeCommand` **不会因为非零退出码抛异常**，所以「成功」判断必须显式看 `exitCode` —— 不加这一句，熔断永远不会触发。 **诚实**：`officecli --version` 在我这边（同一个 rootfs）**正常返回 1.0.152，退出码 0**，所以 core dump 是**设备/机型特定**问题，无法在沙箱复现；本版的价值是「即使崩了也不再产生文件」。 **━━ 四、Linux 能力实测（不是宣称，是跑出来的）━━** | 项 | 实测 | |---|---| | gcc | 13.3.0，编译 hello 成功 | | apt | 2.8.3 (arm64) 可用 | | Python | 中文 + emoji 输出正常 | | Node | v18.19.1 | | 中文字体 | 39 个 | | git / pandoc / texlive / tesseract | 在 | 工具描述里新增一条自检命令，模型不用再一个个试。 **━━ 五、为什么这层地基决定后面能不能做大事 ━━** 你在 App 里看到的文件 = 模型改的文件（同一目录）；装的 Python 包/编译器跨会话存在（rootfs 随工作区）；连续操作低开销；真 Linux 工具链；崩溃不产生垃圾。**有了这五条，下一步才谈得上做「环境快照回滚」「预置工具链」「沙箱状态可视化」这类真正提效的东西。** **━━ 六、诚实边界 ━━** ①**默认行为变了**：依赖「每条命令干净环境」的自定义流程需显式传 `session="none"`；②**同 session 内命令串行**（这是不串状态的前提）；③`/proc/version` 权限拒绝是 proot

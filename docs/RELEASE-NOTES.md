`PYTHONDONTWRITEBYTECODE=1`（不写 `__pycache__`——沙箱冷启动时这类小文件写入既慢又可能因权限/时间戳导致「上次能跑这次报错」）。 **━━ Bug 3：Shell 尤其是渲染类命令慢得惊人 ━━** **根因（结构性）**：`workspace_shell` 每次调用都是**一次性 proot 进程** —— 重新载入 rootfs、重建全部 bind mount（`/dev` `/proc` `/sys`、`/dev/shm`、skills、upload、tool_outputs…）、再起 `env -i` + shell。单条命令里 **1~3 秒是纯启动开销，与命令本身无关**；渲染类命令还要在 proot 内再拉一次浏览器内核，于是「渲染一条就慢得惊人」。这也解释了为什么短命令（`ls`）和长命令（渲染）都慢 —— 慢的不是命令，是每次都重启一次沙箱。 **修复（新增常驻会话池，做成可失败旁路）**：新增 `ShellSessionPool`（复用**同一个 proot + bash**）；`workspace_shell` 增加**可选参数 `session`** —— 同一 `session` 名的连续命令共享一个活着的沙箱，**第 2 条起只剩命令本身的耗时**。**默认行为完全不变**（不传 `session` 仍是原来的一次性沙箱），所以这个新机制坏了也只影响「用了 session 的调用」，主链路零风险。 **安全设计**：①会话起不来 / 写失败 / 执行异常 → **自动回退一次性执行**，功能绝不因此不可用；②超时或子进程死亡 → **立刻丢弃整个会话**（避免残留输出污染下一条命令）；③同一 session 用 Mutex 串行，不同 session 互不阻塞；④闲置 5

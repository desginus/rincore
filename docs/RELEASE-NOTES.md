## RinCore v5.3.27
★★★三个用户报的真 bug：分享永久去重 / Python 编码 / Shell 冷启动 🎯**用户报**：①分享文档到本软件后，退出去，这个文档之后很长时间都分享不进来；②转译器（解释器）有问题，模型反复汇报 Python 有问题，日常也有点怪；③Workspace 里 Shell 命令慢得惊人，尤其渲染类。 **━━ Bug 1：分享过一次的文档，之后再也分享不进来 ━━** **根因（代码级实锤）**：`ChatPage` 的分享去重把参数指纹**永久**写进 `SharedPreferences("share_args_v1")`，判定只用 `contains(fingerprint)` —— 指纹 = `text + 所有 file uri` 的 hashCode，**同一个文件第二次分享必然相同** → 命中 → 直接 `return@LaunchedEffect`。表现就是：界面跳转过来了，但什么都不导入，而且**永久如此**（用户说的「很长一段时间」其实是「直到你换文件或清数据」）。这个标记本来是给「防同一 Intent 在 VM 重组/进程重建窗口内被消费两次」用的，那个窗口只有几秒。 **修复**：改成**带时效**（`SHARE_DEDUP_TTL_MS = 30_000`）—— 只有 30 秒内的重复才抑制，过期即允许再次导入；清理策略也从「超过 100 条就全清」改成「只删过期项」。 **━━ Bug 2：模型反复汇报 Python 有问题 ━━** **根因（高置信）**：proot 启动时只设了 `LANG=C.UTF-8` / `LC_ALL=C.UTF-8`，但**精简 rootfs 里通常没有 C.UTF-8 的 locale 定义**（只有 C/POSIX）→ Python 启动时首选编码退化成 **ascii** → 任何中文/emoji 的 `print`、或 stdout 重定向都会抛 `UnicodeEncodeError: 'ascii' codec can't encode character ...`；模型看到 traceback 就报「Python 解释器/转译有问题」，用户侧看到乱码或奇怪失败。**这不是偶发**：只要输出里有非 ASCII 就必现，所以模型会「反复汇报」。 **修复**（不依赖系统 locale 是否存在，直接给 Python 强制 UTF-8）：`PYTHONUTF8=1`（等价全局 `-X utf8`，文件/流/路径全 UTF-8）+ `PYTHONIOENCODING=utf-8`（stdout/stderr/stdin 显式，覆盖老版本）+ `PYTHONDONTWRITEBYTECODE=1`（不写 `__pycache__`——沙箱冷启动时这类小文件写入既慢又可能因权限/时间戳导致「上次能跑这次报错」）。 **━━ Bug 3：Shell 尤其是渲染类命令慢得惊人 ━━** **根因（结构性）**：`workspace_shell` 每次调用都是**一次性 proot 进程** —— 重新载入 rootfs、重建全部 bind mount（`/dev` `/proc` `/sys`、`/dev/shm`、skills、upload、tool_outputs…）、再起 `env -i` + shell。单条命令里 **1~3 秒是纯启动开销，与命令本身无关**；渲染类命令还要在 proot 内再拉一次浏览器内核，于是「渲染一条就慢得惊人」。这也解释了为什么短命令（`ls`）和长命令（渲染）都慢 —— 慢的不是命令，是每次都重启一次沙箱。 **修复（新增常驻会话池，做成可失败旁路）**：新增 `ShellSessionPool`（复用**同一个 proot + bash**）；`workspace_shell` 增加**可选参数 `session`** —— 同一 `session` 名的连续命令共享一个活着的沙箱，**第 2 条起只剩命令本身的耗时**。**默认行为完全不变**（不传 `session` 仍是原来的一次性沙箱），所以这个新机制坏了也只影响「用了 session 的调用」，主链路零风险。 **安全设计**：①会话起不来 / 写失败 / 执行异常 → **自动回退一次性执行**，功能绝不因此不可用；②超时或子进程死亡 → **立刻丢弃整个会话**（避免残留输出污染下一条命令）；③同一 session 用 Mutex 串行，不同 session 互不阻塞；④闲置 5 分钟自动关闭；⑤stderr 合并进 stdout（否则子进程写满 64KB 管道会整条卡死）；⑥唯一标记行（含随机 token）分隔输出与退出码。 **★给模型的引导**：`workspace_shell` 描述里新增 SPEED 段，明确「渲染/转换/构建这类连续命令请复用同一个 session 名」，否则模型不会主动用。 **━━ 诚实交代 ━━** ①**Bug 3 不会自动变快**：默认仍是一次性沙箱（为保证兼容与隔离）；要提速必须**模型主动传 `session`**，或你在对话里要求「用同一个 session 跑」。如果你希望「默认就复用」，告诉我，我改成默认开启（代价是并发命令会串行、以及沙箱状态会跨命令保留）。②**Bug 2 是「高置信根因」而非「你那条报错的原文」**：我按「模型反复报 Python 错」的典型形态定位到编码；如果你手上有模型当时回的那段 traceback，发我一句就能确认（若是 `UnicodeEncodeError` 就是这条，若是 `ModuleNotFoundError` 那是另一回事——rootfs 缺包）。③**没有安装实测**（沙箱无设备），以代码级定位 + tree-sitter + rc check 双 PASS 为据。**★版本纪律**：5.3.26 → **5.3.27**（只改第三位、不进位）。**★改动 5 文件**：`ChatPage.kt`（TTL）/`ProotShellRunner.kt`（Python UTF-8）/`ShellSessionPool.kt`（新增）/`WorkspaceManager.kt`（launchPersistentShell）/`WorkspaceRepository.kt`+`WorkspaceTools.kt`+`RepositoryModule.kt`（接线）。 **★待你验证**：①**同一份文档分享两次**（中间退出应用）→ 第二次**必须**正常导入（这是

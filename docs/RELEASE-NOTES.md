## RinCore v5.3.46
★★三件事一次修完：发布不再重复推两个一模一样的 / 工具 UI 不再糊一长串路径 / 记忆旧格式可一键清理🧹**━━ 一、发布流程：为什么每次发完会立刻再推一个一模一样的 ━━** 你禁止过这件事，我之前也没做到 —— 根因找到了，是**配置文件与自己文件头的注释互相矛盾**：`dev-build.yml` 第 2 行白纸黑字写着「2026-10-20 起：主流程只推 main，本 workflow 仅供实验分支用**手动触发**」，但 `on:` 里**还留着** `push: branches: [\"adopt-3.0.0\"]`。 于是每次发版的完整链条是：`rc release` 只推 main（跑 `build.yml`，正式发版）→ 我为了保持分支同步**补推 adopt-3.0.0** → **触发 `dev-build.yml` 跑一遍完整构建** → 你在 GitHub 上看到「刚发完，又冒出一个一模一样的，唯一区别是 adopt-3.0.0」。 **它其实什么都没发布**（`dev-build` 不创建 release、不碰 main，注释里也这么写），但看起来就像重复发版，而且白烧一次 CI。 **修复**：删掉 `push` 触发，只留 `workflow_dispatch`。**今后补推 adopt 不会再产生任何构建**；需要临时验证实验分支时手动触发即可。 **验证**：全库 grep `adopt-3.0.0`，剩余的只出现在注释与 workflow 名称里，**没有任何自动触发**。 **━━ 二、工具 UI：不再显示路径，改为文件名 + 内容 ━━** 你说的那句「路径在我看来就是一串无意义的乱码，用户无法识别」是对的。而且代码里**本来就有两套做法**：`workspace_read_file` / `workspace_write_file` 早在 v3.11.24 就改成「标题只写『读取文件』，完整路径放展开详情」，**但 `workspace_edit_file` 和 `workspace_show_file` 一直还在标题里拼完整路径** → 你看到的正是这两个。 现在统一：**标题 = 文件名**（`rincore.md`，不是 `/workspace/KEEP-学习分区/.../rincore.md`）；**正文摘要照旧显示内容**（前 10 行 + 语法高亮）；**完整路径只在你自己点开的详情面板里**，以次要小字出现在文件名下面（那时你才需要精确定位）。 编辑详情面板的标题、展示文件的详情标题、多文件时的「首个 + N」全部同一口径。 **━━ 三、记忆系统：三个结构问题 ━━** 你实测报告里的三条，逐条处理： **① `/profile.md` 存在，但说明里写「There is NO profile file」—— 口径矛盾** 这是我的表述不严谨：那句是给**模型新建记忆时**的指令，却读起来像「库里不存在这个文件」。改为 **「Do not create a profile file」**（禁止新建），并补一句：**如果存在旧的 `/profile.md`，把它当普通 fact 条目（不是特殊层、不再置顶），你顺手编辑它时，把还有用的行搬进 `/projects/` 或 `/topics/`，不要继续往里长。** 这样「存量数据」与「规范」不再打架。 **② `/areas/`、`/people/` 不在规定路径内 —— 规范与存量不一致** 这两个目录**是原版 3.1.0 的布局**，你的存量文件还在那里；我在 v5.3.44 改成 `/playbooks/`、`/projects/`、`/topics/` 时没说明存量怎么办。现在明确：**旧布局继续可读** —— `/areas/x.md` 按 `kind: project` 计权、`/people/x.md` 按 `kind: fact` 计权；**不新建**（新知识写进三个新目录），编辑旧文件时顺手把有用内容搬过去。 **③ 13 个旧格式根文件重复 —— 缺一个能清理的入口** 底层（`purgeLegacyFiles`）从 v5.3.23 就存在，判据是「content 不以 `---` 开头」—— **新架构写入必带 frontmatter，所以这条判据不会误删任何新记忆**。但**一直没有 UI 入口**。 现在：记忆页顶栏多一个**删除图标**，**只在库里真有旧格式条目时出现**；点它弹确认，写明「会删多少条、它们当前不注入模型、只删这些旧条目、不可撤销」→ 确认后一次清完。 顺带修正我自己的一处类型错误：`vm.memories` 的每个元素是 `MemoryFile`（不是 `AssistantMemory`），旧格式判据要用 `!isStructured` 而不是 `isLegacy` —— 编译前自查发现并改掉。 **━━ 四、诚实边界 ━━** ①**旧格式清理是物理删除且不可撤销**（这是你要求的「不要再看到重复」的必然代价），所以放在二次确认后面，且只匹配「没有 frontmatter」的条目；②**`/profile.md` 与 `/areas/`、`/people/` 不做自动迁移** —— 自动搬移会改变归属与 kind，风险高于收益；现在模型知道该往哪写、旧文件按什么计权，你点头我再做迁移；③**工具 UI 改动只影响显示**，工具行为、参数、返回值一个字没动；④**无安装实测**（沙箱无设备），以 tree-sitter 三文件 PASS + `rc check` 双 PASS 为据。 **★版本纪律**：5.3.45 → **5.3.46**（只改第三位、不进位）。 ⑩hub=v5.3.46

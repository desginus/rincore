# RinCore 大重构规划 (v4.8.12 → 连续迭代)

> 目标: 消化 126K 行 app 代码中积累的屎山与技术债, 在不破坏任何现有行为的前提下,
> 把代码整理成"AI 拿上手即懂、改起来容易"的形态。
> 前置工程 (已完成): v4.8.10 裂变地图 (docs/APP_MAP.md) + v4.8.11 标注 35 核心文件。
> 本文档 = 分批执行计划。**每批独立验收, CI 绿才进下一批。**

## 2. 重构原则与底线 (不可违反)

1. **行为等价** — 重构 = 代码组织变化, 不改任何运行时行为。每个补丁链的
   **最终语义**必须完整保留 (把多轮补丁的净效果提炼成一段清晰代码, 而非保留补丁堆)。
2. **核心交互链路零风险** — 对话/生成/工具调用/工作区四条主链, 每批改动后必须可回滚
   (git revert 单 commit 即可)。
3. **小步快跑** — 每批一个 commit (或数个细分 commit), CI 绿 + 用户实测通过才进下一批。
4. **先标注后动刀** — 动任何文件前, 该文件必须已有【域】标注 (35 个已标, 其余随批补标)。
5. **不改外部行为面** — UI 文案/设置项/工具名/协议字段一律不动 (除非用户点名)。
6. **测试守护** — 有单测的模块先跑测试; 无测试的核心逻辑 (工具链/压缩/导出) 用
   沙箱等价脚本验证 (参考 v4.8.5 导出验证方法)。

## 3. 分批计划

### Phase 0 — 基建收尾 (1 个版本, 低风险)
- [ ] 旧标注归一: 【原版对齐】/【技术债审计】等旧块与新【域】块合并去重 (只动注释)
- [ ] 死代码扫描与清理: 未引用类/函数/常量 (用 IDE 级静态分析 + 人工复核)
- [ ] 重复代码识别: 跨文件相似块 (报告 + 选择性合并)
- **验收**: CI 绿; 全量编译零警告增量; 无行为变化。

### Phase 1 — GenerationHandler 拆解 (最高优先, 最热文件)
**现状**: 1727 行, 承载: 消息组装/工具池注入/防吸链/图片预算/流式回调/协议强制。
**目标**: 拆为 5-6 个内聚单元 (同包新文件):
- `PromptAssembly` — system + 历史 + 新消息组装 (缓存锚点逻辑)
- `ToolInjection` — 框架工具/域工具/MCP 快照/白名单过滤
- `ToolGuardChain` — 防吸链 (失败聚合/幂等/熔断/意图门控 — 六轮补丁提炼为清晰状态机)
- `ImageBudget` — 图片预算 (五轮补丁提炼)
- `StreamCallback` — 流式 chunk 处理/视觉变换前缀缓存
- `GenerationHandler` 本体 — 编排 (保留类名与公共入口, 调用方零改动)
**原则**: 公共入口签名不变; 内部纯搬运 + 去重; 每个子单元独立可读。
**验收**: CI 绿 + 真机对话/工具调用/图片发送/长对话压缩全流程实测。

### Phase 2 — ChatService 拆解
**现状**: 1623 行, 承载: 会话管理/发送调度/生成编排/压缩执行/通知/保活。
**目标**:
- `ConversationLifecycle` — 会话创建/落盘节流/元数据
- `GenerationScheduler` — sendMessage/dispatchNextQueuedMessage/Job 管理
- `CompressionRunner` — compressConversation (从 ChatService 移出)
- `WakeGuard` — WakeLock/WifiLock 保活 (v3.6.15/v4.7.18 提炼)
**验收**: CI 绿 + 发送/队列/压缩/后台保活实测。

### Phase 3 — UI 大文件拆解 (逐文件推进)
**清单** (按行数降序, 每文件一个 commit):
- SettingProviderDetailPage 1575 → 拆 Provider 配置表单/模型列表/工具选择
- TTSProviderConfigure 1522 → 拆各 TTS 提供商配置块
- WorkspaceDetailPage 1410 → 拆列表/菜单/对话框 (VM 已独立)

**验收**: 每文件拆完即编译 + 对应页面手动过一遍。

### Phase 4 — 渲染体系 (高风险, 谨慎)

"文件内组织拆分", 不动任何渲染逻辑/时序; 拆完必须真机对比渲染表现。
**验收**: 长文/代码块/公式/表格/流式渲染逐项实测。

### Phase 5 — 工具系统与剩余

## 4. 每批的标准流程

```
1. 该批文件补全【域】标注 (若缺)
2. 静态分析: 确认改动范围 (grep 全调用点)
3. 重构执行 (纯搬运/提炼, 不改语义)
4. 本地核验: 括号平衡 + import 完备 + 调用点签名一致
5. CI 绿
6. 用户真机实测 (关键批)
7. 进下一批
```

**回滚预案**: 每批单 commit; 出问题 `git revert` 该 commit 即回稳定态。

---

## 5. 不做的事 (边界)

- 不改任何 UI 文案/布局/交互行为
- 不改协议字段/请求体结构 (那属于功能, 不属于重构)
- 不升级依赖版本 (haze 锁 beta01 等铁律继续有效)
- 不合并"看起来像"但语义不同的重复 (如三层 launchProcess 是合理分层)
- 不在一个版本里混入新功能 (重构版本只做重构)

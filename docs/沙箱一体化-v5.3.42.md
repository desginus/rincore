| rootfs | `Ubuntu 24.04.3 LTS` | 真用户态，不是模拟壳 |

## 二、真正的五个分离点

| # | 分离点 | 表现 | 本轮 |
|---|---|---|---|
| 1 | **会话层** | 每条 `workspace_shell` 都新起 proot，付 1~3s 纯启动开销；`cd`/环境变量不跨调用 | ✅ 已修 |
| 2 | **预热层** | `officecli --version` 在某些 rootfs 上崩溃 → **43MB core dump 写进用户工作区**；失败静默重试 | ✅ 已修 |
| 3 | **能力边界** | LibreOffice 不可用、npm cacache 失败等只写在内部文档，模型不知道 → 反复试错 | ✅ 已补描述 |
| 4 | **诊断能力** | 沙箱坏了/缺件，用户与模型都没有一条命令能看清 | ⚠️ 部分（描述内置自检命令） |
| 5 | **可感知性** | App UI 不显示沙箱状态（是否就绪/正在跑什么） | ❌ 未做，留待下一批 |

## 三、本轮三项改动（全部可失败旁路）

### 1. `workspace_shell` 默认复用常驻会话（v5.3.27 引入但当时是 opt-in）

```kotlin
// v5.3.42：不传 session → 默认 "main"（每工作区一个）
// 传 session="none" 或空串 → 保持旧的一次性隔离行为（逃生口）
```

**为什么现在敢改默认值** —— 复用的安全性此前已逐条补齐：

- `key = "$workspaceId:$sessionKey"`（`WorkspaceRepository:675`）→ **不同工作区绝不串进程**
- 每条命令前重设 `cd`（v5.3.37）→ `cd` 不跨命令污染
- `ensureSession` 检测 `process.isAlive` / `readerAlive`，**死了自动重建**（模型跑 `exit` 也不会永久坏）
- 闲置 5 分钟自动关闭；**会话起不来自动回退一次性**（`ShellSessionPool.run` 内建）

**代价（诚实）**：同一个 session 内命令串行（`Mutex`）。这是 shell 会话的正常语义，也是不串状态的前提。

### 2. 预热健康化（`SandboxPrewarmer`）

| 修复 | 原因 |
|---|---|
| 命令前置 `ulimit -c 0` | 即使 officecli 再崩溃，也**不再产生 43MB core dump 文件** |
| 探测 `--version` → `--help` | 同样加载 34MB 二进制触发页缓存，但避开 `--version` 的崩溃路径 |
| 连续 3 次失败 → 禁用 24h | 旧实现失败后每个输入沿都重试，等于反复制造 core dump |
| **显式判 `exitCode != 0`** | ★`executeCommand` **不因非零退出抛异常**（返回 `WorkspaceCommandResult`），不加这句熔断永远不触发 —— 我第一版就是这么写的，验证时才发现 |

**实测**：`officecli --version` 在本沙箱（同 rootfs）**正常返回 1.0.152，退出码 0** → core dump 是**设备/机型特定**问题，无法在沙箱复现。修复价值在于「崩了也不再产生文件」，而不是消除崩溃本身。

### 3. Linux 能力边界进工具描述

`workspace_shell` 描述新增 `ENVIRONMENT` 段，给一条自检命令：

```bash
python3 -V; node -v; gcc --version|head -1; git --version; fc-list :lang=zh|wc -l; apt-get --version|head -1
```

并保留已有的不可用清单（LibreOffice / Playwright 需 `--no-sandbox` / stderr 噪音白名单）。

## 四、为什么这层地基决定了「后面能做大事」

用户原话：「只有沙箱软件一体化了，我们后面想去做一些大的改动和优化来提升工作效率时，才有可能实现。」

现在具备的能力：

| 能力 | 依据 |
|---|---|
| **同一份文件**：模型改的 = 用户看到的 | `/workspace` 挂 `files/`（同一个目录） |
| **持久环境**：装的 Python 包/编译器跨会话存在 | rootfs 在 `workspaces/<id>/linux`，随工作区备份 |
| **低开销连续操作** | 会话复用后第 2 条起只剩命令本身耗时 |
| **真 Linux 工具链** | apt + gcc + pip + npm + pandoc + texlive + tesseract |
| **崩溃不产生垃圾** | `ulimit -c 0` + 熔断 |

下一批可做（有地基才成立）：
1. 沙箱状态可视化（App UI 显示「沙箱就绪 / 正在执行 X」）
2. 环境快照/回滚（`linux/` 目录已具备，缺 UI）
3. 预置工具链白名单（`rin-tools` 已有 officecli，可扩展）
4. 沙箱健康自检工具（一条命令出报告，含缺件修复建议）

## 五、已知边界（必须说清）

1. **`/proc/version` 权限拒绝** —— proot 固有限制，无法通过代码修复；依赖标准 `/proc` 的程序（LibreOffice）用不了。
2. **core dump 无法在沙箱复现** —— 本机 `officecli` 正常，说明是设备特定；修复是防御性。
3. **会话复用使同 session 命令串行** —— 需要并行时用不同 session 名。
4. **无安装实测** —— 沙箱无设备，改动靠 `rc check` 双 PASS + 逻辑复刻验证。
5. **默认行为变了** —— 依赖「每条命令都是干净环境」的自定义工作流需要显式传 `session="none"`。

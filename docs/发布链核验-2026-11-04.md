## 一、结论

**发布链全环节通过**，且这次是用**新工作流**跑的（`watch` 而非 `sleep` 轮询、`run_for_sha` 而非「最近一个 run」）。

|---|---|---|---|
| 1 | 发版前自检 | `bin/selfcheck` | **14/14 探针**通过 |
| 2 | 环境健康 | `bin/doctor` | **14 通过 / 0 警告 / 0 失败** |
| 3 | 本地静态检查 | `rc check` | PREFLIGHT-PASS + CI-CHECK-PASS |
| 4 | **按 sha 定位 run** | 看 `rc release` 日志 | ✅ `定位本次 push 产生的 CI run（sha=d2d356556）` —— 新逻辑生效 |

**这次没有 `sleep 295` 轮询**：`rc release` 由 `workspace_job` 包住（进程不受工具超时限制），`watch` 用于秒回查状态，`workspace_job status` 用于一次查询。

## 二、本轮验证到的两个新机制

### 1. `run_for_sha` 真的解决了「等错 run」

旧流程：
```bash
rm -rf /tmp/rc_push.log
sleep 20                      # ← 赌新 run 已经创建
rid=$(latest_run_id)          # ← 取最近一个，不校验 sha
ci_cmd wait "$rid" 2700
```
新流程：
```bash
head_sha=$(git rev-parse HEAD)
rid=$(run_for_sha "$head_sha" 150)   # 轮询 15 条直到出现该 sha 的 run
ci_cmd wait "$rid" 2700 "$head_sha"  # wait 内二次校验 head_sha
```
**本轮日志证据**：`定位本次 push 产生的 CI run（sha=d2d356556）…` 出现在 push 之后、wait 之前，说明新路径被走到。旧版这里只会是 `sleep 20` 然后直接开始打 `[ 11s] in_progress`。

### 2. `watch` 的 sha 比对是有效的

```
最近 run: run 41786981071: in_progress - Build & Release d2d356556
sha: d2d356556 = 本地 HEAD ✓（这个 run 就是当前代码）
```
**这一行是防「绿的不是自己代码」的唯一手段**，之前完全没有。

## 三、本轮暴露的两个流程问题（都已修正/记录）

### 问题 1：我用错方法判断「文档索引缺失」

我跑 `grep -c '^- \`' docs/README.md` 得到 8，于是判定「31 个文档只索引了 8 个」。**实际 README 用的是表格（`| 文件 | 用途 |`）而不是列表**，换成按文件名匹配后 **未索引 0 个**。

**教训**：**判断「某个结构是否存在」时，先看它实际用什么形态写**，不要用自己习惯的形态去 grep。这与 v5.3.33 的「前缀 grep 假阳性」、v5.3.34 的「测的不是模型速度」同族 —— **测量方式与目标不匹配**。

### 问题 2：`bin/` 不在仓库里

我在 `rincore-adopt/` 里跑 `ls bin/` 报 `No such file or directory` —— **`bin/` 在 `/workspace/bin`（工作区根），不随仓库、不随 APK 分发**。

**这不是 bug，是需要记住的事实**：工作流工具只存在于我的环境里；用户拿到的 APK 与它们无关。所以「文档里说用 `bin/origin` 查」对用户没有意义，文档要区分**给用户看的**与**给我自己用的**。

## 五、本版内容（诚实）

**零功能改动** —— 全部是文档（`FILE-ORIGIN.md` / `STRUCTURE-MAP.md` / `CODE-NAVIGATION.md` / `EXTENSION-POINTS.md` / `开工状态`）与工作区工具（`bin/` 系列，不随 APK 分发）。

APK **79,736,659B**，与 v5.3.40 的 79,736,655B 相差 4 字节 —— 这是「本版真的没改功能代码」的物理证据。

## 六、已知边界

1. **工作区工具不随 APK 发布** —— `bin/origin`、`bin/symbols`、`bin/deps`、`bin/perfscan`、`bin/watch`、`bin/selfcheck` 只存在于 `/workspace/bin`，用户设备上没有。文档里给用户的验证步骤不应引用它们。
2. **`archive/` 833M 与 `_trash/` 435M 仍未清** —— 前者是旧 APK 对照基准（建议保留），后者是 proot 权限受限文件（删不掉）。
3. **无安装实测**（沙箱无设备）。
4. **`rc release` 仍是阻塞的** —— 用 job 包住即可，但若要「推完立即返回」需要 `--detach`，本轮未做（会改变现有发布链语义，需你确认）。

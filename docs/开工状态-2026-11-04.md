## 五、本批次新发现（下批次优先处理）

### ★ officecli 在 proot 里 core dump（43MB/次）

清理根目录时发现 `/workspace/ `（文件名是**一个空格**）是一个 **43.4MB 的 ELF core dump**：

```
from 'officecli --version'
execfn: '/data/app/.../lib/arm64/libproot_loader.so'
```

**含义**：`officecli --version` 在 proot 内崩溃（SIGSEGV/SIGABRT），内核把 core 写进**当前工作目录**。而 `SandboxPrewarmer` 预热的第一个动作**正是** `officecli --version`。

**为什么值得修**：
- **每次崩溃产生 43MB**，落在 `/workspace`（= 用户工作区的 CWD）→ **用户手机存储被静默吃掉**，且文件名是空格/`core` 之类，用户根本不会注意到；
- 它同时说明「officecli 预热」在某些 rootfs 上**从未成功过**（崩溃即无效），预热收益存疑。

**下批次的处理方向**（两种，都可失败旁路）：
1. **限制 core dump**：给 shell 命令加 `ulimit -c 0`（proot 内）或在 `WorkspaceManager` 启动参数里禁用 core；
2. **改预热探测方式**：`officecli --version` 改 `officecli --help` 或直接 `ls <bin>`，避免触发崩溃路径；并给预热结果加"连续失败 N 次就放弃该机型的 officecli 预热"熔断。
